# EbroZone Component Guidelines

> This document defines the visual and interaction standards for every UI component used throughout EbroZone Version 1.

Components should feel consistent, intuitive, and premium across the entire platform.

---

# Design Philosophy

Every component should communicate:

- Simplicity
- Confidence
- Professionalism
- Friendliness

Users should immediately recognize how every element behaves without needing to learn new patterns.

---

# General Principles

All components should be:

- Consistent
- Accessible
- Responsive
- Reusable
- Easy to understand

Every component should have one clear purpose.

---

# Buttons

Buttons are the primary action elements of the interface.

## Variants

### Primary

Used for the main action on a page.

Examples:

- Book Consultation
- Start Assessment
- Save Changes

---

### Secondary

Used for supporting actions.

Examples:

- Learn More
- View Details

---

### Outline

Used for low-priority actions.

---

### Ghost

Used inside dashboards and toolbars.

---

### Danger

Used only for destructive actions.

Examples:

- Delete
- Remove
- Cancel Booking

---

# Button Rules

Buttons should:

- Have consistent height.
- Use rounded corners.
- Include smooth hover animations.
- Clearly communicate their purpose.

Never place two primary buttons next to each other.

Each section should have one dominant CTA.

---

# Cards

Cards are the primary content container.

Cards should:

- Use generous padding.
- Have soft shadows.
- Use rounded corners.
- Never feel crowded.

Cards should group related information only.

---

# Forms

Forms should:

- Be simple.
- Be easy to scan.
- Validate in real time where appropriate.
- Display helpful error messages.

Long forms should be divided into logical steps.

---

# Inputs

Inputs should include:

- Label
- Placeholder
- Helper text (when needed)
- Error message
- Focus state

Never rely on placeholders as labels.

---

# Dropdowns

Dropdowns should:

- Be searchable when containing many options.
- Close automatically after selection.
- Clearly indicate the selected value.

---

# Modals

Use modals only when users should remain on the current page.

Modals should:

- Focus on one task.
- Be dismissible.
- Support keyboard navigation.

Avoid placing long forms inside modals.

---

# Tables

Tables should prioritize readability.

Include:

- Sorting
- Filtering
- Empty States
- Loading States

Avoid excessive columns.

---

# Badges

Badges communicate status.

Examples:

- Beginner
- Intermediate
- Completed
- Upcoming

Badges should remain compact and visually consistent.

---

# Alerts

Alert types:

- Success
- Warning
- Error
- Information

Alerts should be clear and actionable.

---

# Navigation

Navigation should:

- Remain simple.
- Clearly indicate the current page.
- Highlight important actions.
- Collapse gracefully on mobile devices.

---

# Dashboard Widgets

Widgets should display:

- Progress
- Upcoming Lessons
- Homework
- Bookings
- Quick Actions

Widgets should prioritize actionable information.

---

# Empty States

Every empty state should include:

- Friendly illustration or icon.
- Short explanation.
- Clear next action.

Empty states should encourage users rather than making the interface feel unfinished.

---

# Loading States

Use skeleton loaders instead of spinners whenever possible.

Loading should feel fast and responsive.

---

# Feedback

Every important action should provide immediate feedback.

Examples:

- Success message
- Error message
- Progress indicator
- Confirmation dialog

Users should never wonder whether an action was completed.

---

# Animations

Components should use subtle animations for:

- Hover
- Focus
- Opening
- Closing
- Loading

Animations should improve usability rather than attract attention.

---

# Accessibility

Every component should:

- Support keyboard navigation.
- Include visible focus states.
- Meet WCAG AA contrast requirements.
- Include accessible labels where necessary.

Accessibility is required for every component.

---

# Component Consistency

Every component should share:

- The same spacing system.
- The same border radius.
- The same typography.
- The same color palette.
- The same animation style.

The goal is to make every page feel like part of a single, unified product.

---

# Success Criteria

A successful component system ensures that:

- Users instantly understand how components behave.
- Interfaces remain visually consistent.
- Development becomes faster through reusable components.
- AI can generate new interfaces without introducing inconsistencies.
