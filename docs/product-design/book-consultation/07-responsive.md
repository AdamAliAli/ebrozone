# Book Consultation Responsive Behavior

Version: v1.0

Status: Approved for Development

---

# Purpose

This document defines how the Book Consultation page adapts across different devices.

Only page-specific responsive behavior is documented here.

---

# Responsive Goals

The page should:

- Keep the consultation form easy to complete.
- Maintain readability.
- Keep the primary CTA visible.
- Avoid unnecessary scrolling.

---

# Navigation

Desktop

- Full navigation.

Tablet & Mobile

- Hamburger menu.

---

# Introduction

Desktop

- Centered content with comfortable spacing.

Mobile

- Reduced spacing while maintaining readability.

---

# Consultation Benefits

Desktop

- Three-column layout.

Tablet

- Two-column layout.

Mobile

- Single-column layout.

---

# Consultation Form

Desktop

- Centered card with a comfortable reading width.

Tablet

- Slightly narrower spacing.

Mobile

- Full-width form.
- Full-width submit button.
- Inputs stacked vertically.

---

# Process Timeline

Desktop

- Horizontal timeline.

Mobile

- Vertical timeline.

---

# FAQ

Accordion remains full width on all devices.

---

# Footer

Desktop

- Multi-column layout.

Mobile

- Single-column layout.

---

# Mobile Priorities

Mobile users should be able to:

- Complete the form with one hand.
- Easily tap every field.
- Submit the request without zooming.

---

# Success Criteria

Responsive behavior is successful when:

- The consultation form is easy to complete on every device.
- No functionality is lost.
- The booking experience remains simple and intuitive.
